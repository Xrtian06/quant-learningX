# Phase 5：实战场 — 纸交易系统

> **设计日期**：2026-04-25  
> **适用对象**：大一金融工程学生，已完成 Phase 4 心法篇  
> **时间投入**：每天1小时，共4-5周  
> **学习目标**：搭建一个能连接模拟账户、接收策略信号、自动/半自动执行交易的系统框架

---

## 🎯 牵引项目

**项目名称**：🚀 纸交易系统 (Paper Trading System)  
> 一个可运行的纸交易框架，能接收策略信号、模拟下单、记录持仓和交易日志。

**最终交付物**：`paper_trading_system/` 文件夹，含策略、风控、执行、日志模块，能在模拟环境中半自动运行。

---

## 🗓️ 周计划拆解

### 第1周：交易执行基础

**核心任务**：理解真实交易与回测的区别。

**学习内容**：
- 回测 vs 真实交易的关键差异：
  - **滑点（Slippage）**：下单价格与实际成交价格的差异
  - **延迟（Latency）**：从信号生成到订单提交的时间
  - **部分成交**：大单不一定能一次全部成交
  - **涨跌停限制**：A股有10%涨跌停，策略信号可能无法执行
- 模拟交易平台的认识：同花顺模拟炒股、雪球组合、聚宽模拟交易
- **论文素养植入**：写一段分析——为什么很多回测表现极好的策略，实盘后效果大打折扣？

**项目里程碑**：✅ 在聚宽或同花顺开设模拟账户，手动按策略信号操作一周，记录差异。

---

### 第2周：API 与自动化基础

**核心任务**：学会用代码与交易接口"对话"。

**学习内容**：
- 量化交易 API 的基本概念：请求格式、认证方式、限频规则
- 用 `easytrader` 或券商量化接口（如QMT、迅投）获取账户信息
- 写一个 `MockBroker` 类：模拟下单、查询持仓、查询资金（为后续对接真实接口做准备）
- 理解"异步"与"回调"：真实交易是事件驱动的

**项目里程碑**：✅ 完成 `MockBroker` 模块，能模拟买入/卖出、更新持仓、记录交易流水。

---

### 第3周：事件驱动框架

**核心任务**：理解专业量化系统的架构。

**学习内容**：
- 事件驱动架构：DataHandler → Strategy → Portfolio → ExecutionHandler
- 用 Python 的 `queue` 模块搭建简单的事件循环
- 把 Phase 2-4 的策略改造成"事件驱动"形式（不再是一次性回测，而是逐日接收数据、逐日决策）

**项目里程碑**：✅ 一个最小可用的事件驱动回测/纸交易混合系统：既能用历史数据模拟运行，也能预留接口对接真实数据。

---

### 第4-5周：纸交易系统整合

**核心任务**：把前面所有模块串成一个系统。

**学习内容**：
- 整合 Phase 3 的策略信号 + Phase 4 的风控模块 + Phase 5 的交易执行
- 设计交易日志格式：记录每笔交易的时间、信号、成交价、手续费、滑点估计
- 每日收盘后生成"交易日报"：持仓、盈亏、资金曲线
- 对接模拟交易 API（如聚宽、QMT），实现半自动运行（策略生成信号，人工一键确认下单）

**项目里程碑**：✅ **纸交易系统 v1.0** 完成——每日自动产生交易信号和风控提示，人工确认后执行（或全自动在模拟环境中运行）。

## ⏰ 每天1小时分配建议

Phase 5 涉及很多"工程化"内容（API、异步、系统架构），代码调试时间会增加。

| 时间块 | 内容 | 说明 |
|--------|------|------|
| **25分钟** | 学概念/读文档 | API 文档通常枯燥但必须耐着性子看 |
| **30分钟** | 编码调试 | 事件驱动代码容易出逻辑bug，多打印日志 |
| **5分钟** | 写系统日志 | 记录今天解决了什么问题，明天继续什么 |

> ⚠️ **重要提醒**：Phase 5 不需要也不建议用真实资金！所有交易都在**模拟账户**中进行。

## 💡 给未来论文的铺垫

在"回测 vs 实盘差异"分析中，尝试用学术规范讨论以下问题：

1. **问题定义**：回测中的哪些假设在真实交易中不成立？
2. **文献关联**：学术界如何衡量"回测过拟合"和"执行落差"（Implementation Shortfall）？
3. **实证观察**：你在模拟交易中观察到的差异有哪些？
4. **启示**：这些差异对量化研究的方法论有什么启示？

这是量化金融中"市场微观结构"和"执行成本"领域的入门思考，也是很多高质量论文的讨论部分会涉及的内容。
